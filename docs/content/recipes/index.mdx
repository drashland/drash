# Recipes

A recipe is one finished job. It states what you are building, shows the complete file for your runtime, then takes that file apart.

That is a different shape from [Docs](/docs/getting-started), which explains one feature at a time &mdash; what a resource is, how params are read, where errors go. Those pages answer "how does this work." These answer "I want to build X, show me the whole thing."

## Pick Your Runtime

Each runtime is a section in the sidebar, and each page under it is one complete, runnable application for that runtime. Nothing is shared between them at runtime, so read only the one you need.

Start with the basic app. It is the same application on every runtime &mdash; one resource answering `GET /` &mdash; so reading the one that matches your setup makes the differences between the others stop being mysterious.

## What Changes Between Runtimes

The resource and the application are identical in every one of the basic recipes. What differs is the entry point &mdash; see [About > Concepts > Native vs. Polyfill](/about/concepts/native-vs-polyfill) &mdash; and how your runtime hands you a request.

| | Entry point | What the resource receives |
| --- | --- | --- |
| Bun | `http.polyfill.js` | Web `Request` |
| Cloudflare Workers | `http.native.js` | Web `Request` |
| Deno | `http.native.js` | Web `Request` |
| Node (ESM / CJS / TS) | `http.polyfill.js` | Context object you build |
| Vercel (`api/`) | `http.polyfill.js` | Web `Request` |
| Vercel (`server.ts`) | `http.polyfill.js` | Context object you build |

<Callout type="gray">
  Every basic recipe catches `favicon` requests in its `.catch()`. Browsers
  request `/favicon.ico` automatically, and no resource owns that path, so the
  chain throws a `404` for it. That check keeps the noise out of the console; it
  is not something your own app needs.
</Callout>

## What Every Recipe Assumes

- Your runtime is installed. If you do not have one yet, the [quickstart](/docs/quickstart) sets one up.
- You have read, or are willing to click through to, [Creating a Resource](/docs/resources/creating-a-resource).

Nothing else. Each recipe names its own dependencies at the top and links out rather than repeating what another page already says.
