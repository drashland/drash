# Resource

A resource maps a set of paths to HTTP method handlers. It is the unit you write most.

```ts
class Users extends Resource {
  public paths = ["/users/:id?"];

  public GET(request: Chain.HTTPRequest) {
    return new Response(`User ${request.params.pathParam("id")}`);
  }
}
```

## `paths`

An array of `URLPattern` pathname patterns.

```ts
public paths = ["/", "/home", "/users/:id?"];
```

Drash appends `{/}?` to each pattern when compiling, so `/users` also matches `/users/`.

## Dynamic paths

Paths can carry parameters and regular expressions, so one resource can cover many endpoints.

### Required path params

```ts filename="ResourceWithPathParam.ts"
class ResourceWithPathParam extends Resource {
  paths = ["/:my_param"];

  GET(request: Chain.HTTPRequest) {
    return new Response(`You passed in: ${request.params.pathParam("my_param")}`);
  }
}
```

```text
GET /hello      ->  You passed in: hello
GET /world      ->  You passed in: world
```

### Optional path params

A trailing `?` makes a param optional, so the resource matches with or without it.

```ts filename="Users.ts"
class Users extends Resource {
  // id is required; the rest are optional
  paths = ["/users/:id/:name?/:age?/:city?"];

  GET(request: Chain.HTTPRequest) {
    const id = request.params.pathParam("id");
    const name = request.params.pathParam("name");
    return new Response([id, name].filter(Boolean).join(" | "));
  }
}
```

```text
GET /users/1             ->  1
GET /users/1/            ->  1
GET /users/1/John        ->  1 | John
GET /users/1/John/       ->  1 | John
```

You can have as many optional params as you like, but **required params must come before optional ones**.

### Regular expression paths

```ts filename="RegexPathResource.ts"
class RegexPathResource extends Resource {
  paths = ["/([0-9]$)"];

  GET(_request: Request) {
    return new Response("GOT!");
  }
}
```

```text
GET /1  ->  GOT!
GET /2  ->  GOT!
```

## HTTP methods

Override any of:

`CONNECT` `DELETE` `GET` `HEAD` `OPTIONS` `PATCH` `POST` `PUT` `TRACE`

Each receives the input that was passed to `chain.handle()` and you return whatever your runtime needs.

**Every method you do not override throws `HTTPError(501 Not Implemented)`.** That is the base class behavior, following [RFC 7231 Section 4.1](https://datatracker.ietf.org/doc/html/rfc7231#section-4.1).

Methods may be synchronous or asynchronous; `chain.handle()` awaits whatever they return.

```ts
class Home extends Resource {
  public paths = ["/"];

  public GET(request: Request) {
    return new Response("Hello");
  }

  // POST, PUT, DELETE, ... all throw 501
}
```

To return `405` instead, override the method and throw explicitly:

```ts
public PATCH(_request: Request) {
  throw new HTTPError(Status.MethodNotAllowed);
}
```

## Return Values

Whatever an HTTP method returns becomes the resolved value of `chain.handle()`. For runtimes that support Web `Request`/`Response`, the HTTP method should return `Response`. Otherwise, the HTTP method should return whatever the runtime needs. In Node, you do not have to return anything since it expects you to write directly to the `ServerResponse` object it gives you.

<Callout type="warning" emoji={null}>
__HTTP methods in middleware__

An HTTP method wrapped in middleware must return a value. Otherwise, `Middleware.next()` (under the hood) throws an error because it expects a return value from the wrapped method.
</Callout>

## Request params

`RequestParamsParser` attaches a non-enumerable `params` object to the request. Use the `Chain.HTTPRequest` type on the request argument to see it:

```ts
import * as Chain from "@drashland/drash/modules/chains/RequestChain/mod.native.js";

class Users extends Resource {
  public paths = ["/users/:id?"];

  public GET(
    request: Chain.HTTPRequest // <--- Has Chain.HTTPRequest type
  ) {
    const id = request.params.pathParam("id");
    const sort = request.params.queryParam("sort");
    return new Response(`id=${id} sort=${sort}`);
  }
}
```

`Chain.HTTPRequest` has the following methods:

| Method             | Returns               | Notes                                    |
| ------------------ | --------------------- | ---------------------------------------- |
| `pathParam(name)`  | `string \| undefined` | From the matched `URLPattern`            |
| `queryParam(name)` | `string \| undefined` | From the query string — see caveat below |

Both return `undefined` for a missing name rather than throwing.

<Callout type="warning">
  **`queryParam()` does not return the first query parameter.** It is built from
  `new URLSearchParams(request.url)`, which parses the entire URL as a query
  string rather than just the part after `?`. The first parameter's name is
  absorbed into the URL prefix, so for
  `http://localhost:1447/users/1?sort=asc&page=2`:

```ts
request.params.queryParam("sort"); // undefined
request.params.queryParam("page"); // "2"
```

  Every parameter after the first behaves correctly. Until this is fixed, read
  the query string yourself when you need the first parameter:

```ts
const sort = new URL(request.url).searchParams.get("sort");
```

</Callout>

## `Resource.group()`

Shorthand for a resource group builder. See [Resource groups](/docs/reference/resource-group).

```ts
const group = Resource
  .group()
  .middleware(Auth)
  .pathPrefixes("/api/v1")
  .resources(Users)
  .build();
```
