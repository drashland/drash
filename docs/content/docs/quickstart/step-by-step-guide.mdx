# Step-By-Step Guide

## Overview

This guide builds a tiny HTTP application with the Request Chain module, one piece at a time. If you want the finished app rather than the walkthrough, the per-runtime [quickstarts](/docs/quickstart) have it in one block.

### Recommended reading

- Complete the [Prerequisites](/docs/getting-started/prerequisites)
- Read the concepts on [chains](/docs/concepts/chains) and [resources](/docs/concepts/resources)

### Objectives

Familiarity with:

- the Request Chain, without using the [`await`](https://developer.mozilla.org/en-US/docs/Web/JavaScript/Reference/Operators/await) operator;
- how it is used in different runtimes;
- how resources handle requests; and
- how to send responses based on those requests.

## Instructions

You will end up with a single file, `app.ts` (or `app.js` in Node).

Each step **adds** to the code from the step before it. The comments explain the code line by line.

**1. Create a resource.**

A resource is the target of a request. `paths` says which URLs it answers to, and the HTTP method names say how.

```ts filename="app.ts"
import {
  Chain,
  Resource,
} from "@drashland/drash/modules/chains/RequestChain/mod.native.js";

class Home extends Resource {
  paths = ["/"];

  GET(request: Request) {
    console.log(`Request received: ${request.method} ${request.url}`);
    return new Response(`Written at: ${new Date()}`);
  }
}
```

**2. Build the chain.**

Build it once, at module scope — not per request.

```ts filename="app.ts"
const chain = Chain
  .builder()
  .resources(Home)
  .build();
```

**3. Plug the chain into the runtime's HTTP server.**

Deno hands you a Web `Request` and wants a `Response` back, which is exactly what the chain takes and returns.

```ts filename="app.ts"
Deno.serve({ hostname: "localhost", port: 1447 }, (request: Request) => {
  return chain.handle<Response>(request);
});
```

**4. Handle errors.**

`chain.handle()` rejects on error and writes nothing for you, so the `.catch()` decides what the client sees.

```ts filename="app.ts"
Deno.serve({ hostname: "localhost", port: 1447 }, (request: Request) => {
  return chain
    .handle<Response>(request)
    .catch(() => new Response("Internal Server Error", { status: 500 }));
});
```

**Run it:**

```bash
deno run --allow-net app.ts
```

**1. Create a resource.**

Node's `node:http` does not give you a Web `Request`, so the resource receives a **context object** that you build. It only has to carry a readable `url` and `method`; everything else is yours.

```js filename="app.js"
import {
  Chain,
  Resource,
} from "@drashland/drash/modules/chains/RequestChain/mod.polyfill.js";
import { createServer } from "node:http";

class Home extends Resource {
  paths = ["/"];

  GET(context) {
    console.log(`Request received: ${context.method} ${context.url}`);
    context.response.end(`Written at: ${new Date()}`);
  }
}
```

**2. Build the chain.**

```js filename="app.js"
const chain = Chain
  .builder()
  .resources(Home)
  .build();
```

**3. Plug the chain into the runtime's HTTP server.**

`url` must be a fully qualified URL. `request.url` from `node:http` is path-only, so prefix it.

```js filename="app.js"
const hostname = "localhost";
const port = 1447;

const server = createServer((request, response) => {
  const context = {
    url: `http://${hostname}:${port}${request.url}`,
    method: request.method,
    request,
    response,
  };

  return chain.handle(context);
});

server.listen(port, hostname);
```

**4. Handle errors.**

```js filename="app.js"
return chain.handle(context).catch(() => {
  response.statusCode = 500;
  response.end("Internal Server Error");
});
```

**Run it:**

```bash
node app.js
```

Bun and Cloudflare Workers follow the same four steps — only the import and the server call change. See the [Bun](/docs/quickstart/bun) and [Cloudflare Workers](/docs/quickstart/cloudflare-workers) quickstarts.

## Verification

With the app running, go to `http://localhost:1447` in your browser. You should see something like:

```text
Written at: Sun Aug 20 2023 19:47:48 GMT-0400 (Eastern Daylight Time)
```

and in your terminal:

```text
Request received: GET http://localhost:1447/
```

If both appear, the app is working.

<Callout type="info">
  Browsers also request `/favicon.ico`. Because no resource owns that path, the
  chain throws a `404` for it — which is why some examples special-case
  `favicon` in their `.catch()`. It does not mean your app is broken.
</Callout>
