# Native vs. Polyfill

In some cases, Drash's modules have two consumer entry points:

- `<module_name>.native.js`
- `<module_name>.polyfill.js`

This is to accomodate runtimes that do not fully support Web Standards. In other words, they do not fully implement [Web APIs](https://developer.mozilla.org/en-US/docs/Web/API).

For example, the HTTP module has the following entry points:

```
@drashland/drash/modules/http.native.js   // Supports global URLPattern
@drashland/drash/modules/http.polyfill.js // Requires polyfill for URLPattern in older versions
```

The HTTP modules export **the same surface** — `Chain`, `Resource`, `Middleware`, `HTTPError`, and the `HTTPRequest` type. The only difference is which `URLPattern` implementation is used under the hood:

Tutorials will call out if there is a need for you to choose. If you are unsure, polyfill modules should work everywhere. Polyfill modules are bundled, so they cost little size but no network or peer dependency.
