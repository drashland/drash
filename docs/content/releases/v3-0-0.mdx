# v3.0.0

**25 August 2026**

The first stable release of v3, and a complete rewrite. Drash v2 was a Deno web framework built around its own HTTP server. v3 is not an HTTP server wrapper: it is a runtime-agnostic library that runs the same application code on Deno, Node, Bun, and Cloudflare Workers.

<Callout type="warning">
__v3 is not backwards compatible with v2.__ Nothing is deprecated and nothing is shimmed; the API is different because the shape of the framework is different. v2 remains on the `v2.x` branch.
</Callout>

## How Long This Took

The first v3 preview shipped in __October 2023__, with the final beta in __January 2024__. Then the project went quiet for years. That matters for anyone considering a dependency: open source is unpaid work, and teams maintain it through passion&mdash;not obligation.

What the gap here means in practice:

- The published npm package lagged the source for most of that period. The docs went out of date as the runtimes continued to progress through the years.
- The v3 API itself did not drift while nobody was working on it. Most of what changed between the last beta and now is naming, documentation, and its support for runtimes.

## What Drash v3 Is

**A chain of handlers you build once and hand requests to.** Drash is not an HTTP server wrapper. You build an application and plug it into your runtime's server—`Deno.serve`, `node:http`, `Bun.serve`, a Worker's `fetch`—to handle its request-response lifecycle.

```ts
import {
  Application,
  Resource,
} from "@drashland/drash/modules/http.native.js";

class Home extends Resource {
  paths = ["/"];

  GET(request: Request) {
    return new Response("Hello from Drash.");
  }
}

const app = Application.builder().resources(Home).build();

Deno.serve({ port: 1447 }, (request) =>
  app
    .handle<Response>(request)
    .catch(() => new Response("Internal Server Error", { status: 500 })));
```

That last `.catch()` is not decoration. `app.handle()` returns a promise and
**rejects on error, including a 404**. Nothing downstream turns that into a
response, so without a `.catch()` the request hangs.

## What Changed From v2

| | v2 | v3 |
| --- | --- | --- |
| Runtimes | Deno only | Deno, Node, Bun, Cloudflare Workers |
| Server | Bundled (`Drash.Server`) | None — you bring your own |
| Request / response | Drash `Request` and `Response` wrappers | Web `Request` and `Response`, or a context object you define |
| Resource input | `this.request`, `this.response` | Passed as an argument to the method |
| Middleware | `Service` | `Middleware`, attached with `ResourceGroup` |
| Errors | `ErrorHandler` | `HTTPError`, caught where you call `handle()` |

The removals are deliberate: `this.request` and `this.response` made resources stateful for a single request. However, it prevented safe reuse across concurrent requests. Resources now initialize at build time and are reused for the app's lifetime&mdash;eliminating per-request object creation. It's a tradeoff among performance, semantics, and maintainability.

## What Ships (Native vs. Polyfill)

**There are two entry points to create an HTTP application.**

- `modules/http.native.js`
- `modules/http.polyfill.js`

They export the same six members. They differ only in which `URLPattern` they hand
the router — the runtime's global, or Drash's bundled polyfill. See
[Native vs. Polyfill](/docs/concepts/native-vs-polyfill).

| Export | Kind |
| ------ | ---- |
| `Application` | class |
| `Resource` | class |
| `Middleware` | class |
| `ResourceGroup` | class |
| `HTTPError` | class |
| `HTTPRequest` | type |

**Four middleware**, none runtime-specific:
[`AcceptHeader`](/reference/modules/middleware/accept-header),
[`CORS`](/reference/modules/middleware/cors),
[`ETag`](/reference/modules/middleware/etag), and
[`RateLimiter`](/reference/modules/middleware/rate-limiter).

**Three builders** for constructing requests, responses, and the request chain
itself — see [Modules > Builders](/reference/modules/builders).

**Documentation**, which is new in this release: concepts, a quickstart per
runtime, a full API reference, runnable examples, and
[agents.md](https://drash.crookse.com/agents.md) for coding agents.

## Supported Runtimes

Every runtime below has its own compatibility suite in CI, run against the built
package rather than the source.

| Runtime | Entry point | What a resource method receives |
| ------- | ----------- | ------------------------------- |
| Deno | `http.native.js` | Web `Request` |
| Node 20, 22, 24, 26 | `http.polyfill.js` | A context object you build |
| Bun | `http.polyfill.js` | Web `Request` |
| Cloudflare Workers | `http.native.js` | Web `Request` |

Node uses the polyfill entry point because `URLPattern` support varies across
those majors. Bun uses it because its `URLPattern` is not dependable.

## Coming From v2

There is no migration tool. The concepts that carry over are resources and
paths; everything around them is different. Read
[Resources](/docs/concepts/resources) first — it is the piece of v2 that
survived, and the rest of the API is built around it.
