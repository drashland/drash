# Native vs. Polyfill

The HTTP module ships two consumer entry points. They are interchangeable: same exports, same behavior, same types. The only difference is which `URLPattern` implementation gets wired into the chain for you.

```
import { ... } from "@drashland/drash/modules/http.native.js";
import { ... } from "@drashland/drash/modules/http.polyfill.js";
```

For the reasoning behind the split, see the [Concepts > Native vs. Polyfill](/docs/concepts/native-vs-polyfill) page.

## Exports

Both entry points export the same five members. Nothing is available from one and missing from the other, so switching between them never changes an import list:

| Export        | Kind  | Reference                                                  |
| ------------- | ----- | ---------------------------------------------------------- |
| `Chain`       | class | [Chain](/reference/modules/chain)                     |
| `Resource`    | class | [Creating a Resource](/docs/resources/creating-a-resource) |
| `Middleware`  | class | [Middleware](/docs/tutorials/middleware)                   |
| `HTTPError`   | class | [HTTPError](/reference/core/errors/http-error)                    |
| `HTTPRequest` | type  | The request shape a resource method receives               |

## What Each One Injects

Each entry point calls [`.urlPatternClass()`](/reference/modules/chain#urlpatternclass) on your behalf. For example:

| Entry point        | `URLPattern` used                      | Source of the implementation |
| ------------------ | -------------------------------------- | ---------------------------- |
| `http.native.js`   | `.urlPatternClass(URLPattern)`         | The runtime                  |
| `http.polyfill.js` | `.urlPatternClass(URLPatternPolyfill)` | Drash's implementation       |

If you need a custom implementation, you can call `.urlPatternClass()` yourself. See [Modules > HTTP > Chain > urlPatternClass()](/reference/modules/chain#urlpatternclass) to learn more.

## Choosing One

Use `http.native.js` where the runtime provides a global `URLPattern`, and `http.polyfill.js` everywhere else. The [Quickstart overview](/docs/quickstart) lists which runtimes fall on which side.

If you are unsure, the polyfill entry point works everywhere, including runtimes that do have a global `URLPattern`.

## Choosing Wrong

Picking `http.native.js` on a runtime with no global `URLPattern` fails while the chain is being built, not on the first request:

```text
`this.urlPatternClass(Resource)` not called. Cannot create RequestChain without a `URLPattern`-like class.
```

Because chains are normally built once at startup, this surfaces as soon as the process boots rather than as an intermittent routing failure under traffic.

## Supplying Your Own

Neither entry point locks you in. `Chain.builder()` accepts any `URLPattern`-compatible class through [`.urlPatternClass()`](/reference/modules/chain#urlpatternclass), which overrides whatever the entry point injected.
