# Modules

The pieces that do the work, composed from [Standard](/reference/standard) and [Core](/reference/core). This is the layer an application imports from.

## The Two Entry Points

`modules/http.native.js` and `modules/http.polyfill.js` export the same members. The only difference is which `URLPattern` implementation they use under the hood.

| Entry point                | For                              |
| -------------------------- | -------------------------------- |
| `modules/http.native.js`   | Deno, Cloudflare Workers         |
| `modules/http.polyfill.js` | Node, Bun                        |

See [Native vs. Polyfill](/reference/modules/http/native-vs-polyfill).

<Callout type="warning" emoji={null}>
__Any change to one entry point has to be mirrored in the other.__ They are separate files with the same surface, and the compat tests exist in `native/` and `polyfill/` pairs for that reason.
</Callout>
